WHY IT WAS REJECTED

tests/test_schema_compatibility.py::test_migrations_are_schema_agnostic:

  "Object names must be unqualified so the same artifacts apply to rigid_foam
   and to a disposable test schema. A hard-coded schema name would make
   'applies cleanly to a pre-change database' untestable."

This artifact writes "rigid_foam._backup_recipe_versions_20260819" and
"rigid_foam._backup_recipe_components_20260819" in four places. It was the only
artifact in the repository breaking that rule; the other twenty conform.

The fault was avoidable and specific. A relocation must name its DESTINATION -
that is inherent to ALTER TABLE ... SET SCHEMA. It does not need to name the
SOURCE, which resolves through search_path like every other migration's
objects. The consequence showed itself during the proof: the disposable-schema
run had to use a hand-written equivalent rather than the artifact itself,
because the artifact could only ever address rigid_foam. That was the signal,
and it was worked around instead of followed.

Charlie: "Option B would weaken a working QA rule to accommodate one avoidable
artifact defect. Option C would knowingly carry a non-conforming migration and
a red regression suite into later work. Neither is acceptable."
